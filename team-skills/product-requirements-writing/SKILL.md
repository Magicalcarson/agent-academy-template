# Product Requirements Writing

Use this skill to convert an idea, feature request, workflow problem, or rough note into a product requirement that a team can review and implement.

## Workflow

1. Describe the current problem, affected users, evidence, and cost of leaving it unresolved.
2. Capture the current workflow, target workflow, handoffs, exceptions, corrections, and failure states.
3. Define the smallest useful scope, deferred work, and explicit non-goals.
4. Express user needs without assuming a particular interface or implementation prematurely.
5. Write observable acceptance criteria covering permissions, validation, empty states, errors, recovery, audit needs, and accessibility where relevant.
6. Identify privacy, security, financial, legal, operational, adoption, and data-quality risks that genuinely apply.
7. Split implementation into independently reviewable slices with dependencies and verification signals.

Keep facts, assumptions, decisions, and open questions separate. Do not turn an example into a universal requirement or hide unresolved product choices inside implementation detail.
